⚡ Why Reqix?

        

          Modern web applications frequently communicate with custom backend APIs (Go, FastAPI, NestJS, Django, Spring,
          or Rails) that issue short-lived access tokens (e.g., 5-minute expiry) and rotating
            refresh tokens.
        

        

          Existing libraries introduce significant friction into modern full-stack architectures:
        

        
    
          
  • 
            The Thundering Herd Bug: When a user navigates to a dashboard, 10 parallel components
            fire API calls at once. If the access token is expired, naive interceptors fire 10 simultaneous refresh
            calls.
            When using rotating refresh tokens, the second call invalidates the user's session and forces an abrupt
            logout.
          
    • 
          
  • 
            Next.js Cookie Constraints: React Server Components (RSC) cannot modify cookies during
            streaming
            render. Naive auth wrappers crash with
            Error: Cookies can only be modified in a Server Action or Route Handler.
          
    • 
        


        

          💡
          

            Reqix is headless: You own your backend network requests and your storage model (cookies or
            localStorage).
            reqix guarantees single-flight deduplication, cross-tab synchronization via Web Locks, and
            proactive Edge middleware refresh.

🌐 Mode 1: Pure HTTP Client (Without Auth)

        

          If your project only needs a lightweight, type-safe alternative to Axios or fetch
          (e.g., calling public APIs, internal microservices without JWT token rotation), use
          createHttpClient.
        


        
1. BaseURL & Default Client Configuration

        

          Configure your HTTP client once in lib/api.ts. You can set a global baseURL, default
          headers,
          timeouts, and automatic retry behaviors:
        


        

          

            

              

                
                
                
              

              

                TS
                lib/api.ts
              

            

            

              
            

          

          
// lib/api.ts
import { createHttpClient } from 'reqix';

// Initialize the standalone HTTP client
export const http = createHttpClient({
  // 1. Base URL automatically prepends to all relative paths
  baseURL: process.env.NEXT_PUBLIC_API_URL || 'https://api.example.com',

  // 2. Default headers attached to every outgoing request
  headers: {
    'Content-Type': 'application/json',
    'Accept': 'application/json',
    'X-Client-Platform': 'web',
  },

  // 3. Per-attempt timeout in milliseconds
  timeout: 8000,

  // 4. Automatic Retries on network errors or 5xx status codes
  retry: 2, // 2 retry attempts with exponential jitter backoff
  retryStatusCodes: [408, 429, 500, 502, 503, 504],
});

        


        
2. Making API Calls: GET, POST, PUT, PATCH, DELETE

        

          All HTTP methods are fully typed, automatically parse JSON response bodies, and return an
          HttpResponse<T>:
        


        

          

            

              

                
                
                
              

              

                TS
                features/posts/api.ts
              

            

            

              
            

          

          
import { http } from '@/lib/api';

export interface Post {
  id: number;
  title: string;
  body: string;
  author: string;
}

// ----------------------------------------------------------------------------
// GET: Query Parameters with automatic serialization
// ----------------------------------------------------------------------------
export async function getPosts(page = 1, search = ''): Promise<Post[]> {
  // Results in: GET https://api.example.com/api/posts?page=1&limit=10&search=nextjs
  const res = await http.get<Post[]>('/api/posts', {
    params: { page, limit: 10, search },
  });
  return res.data; // Already parsed Post[] array!
}

// ----------------------------------------------------------------------------
// POST: JSON Request Payload
// ----------------------------------------------------------------------------
export async function createPost(newPost: Omit<Post, 'id'>): Promise<Post> {
  // Results in: POST https://api.example.com/api/posts
  const res = await http.post<Post>('/api/posts', newPost);
  console.log('Status code:', res.status); // 201
  return res.data;
}

// ----------------------------------------------------------------------------
// PUT: Complete Entity Replacement
// ----------------------------------------------------------------------------
export async function updatePost(id: number, updatedPost: Post): Promise<Post> {
  // Results in: PUT https://api.example.com/api/posts/42
  const res = await http.put<Post>(`/api/posts/${id}`, updatedPost);
  return res.data;
}

// ----------------------------------------------------------------------------
// PATCH: Partial Entity Update
// ----------------------------------------------------------------------------
export async function patchPostTitle(id: number, title: string): Promise<Post> {
  // Results in: PATCH https://api.example.com/api/posts/42
  const res = await http.patch<Post>(`/api/posts/${id}`, { title });
  return res.data;
}

// ----------------------------------------------------------------------------
// DELETE: Resource Removal
// ----------------------------------------------------------------------------
export async function deletePost(id: number): Promise<boolean> {
  // Results in: DELETE https://api.example.com/api/posts/42
  const res = await http.delete(`/api/posts/${id}`);
  return res.status === 204 || res.status === 200;
}

🛡️ Mode 2: Next.js Full Auth (With Token Refresh)

        

          When building authenticated Next.js applications backed by a custom JWT backend, you need a solution
          that spans both Server Components (RSC) and Client Components with zero token leaks.
        


        

          ✨
          

            The 6-Step Production Architecture: Follow these 6 steps to configure production-grade
            authentication across your entire Next.js App Router application.
          

        


        

          
          

            

              
1

              

                
Server Session Configuration

                lib/auth.ts
              

            

            

              Configure getServerAuth to read session tokens directly from Next.js cookies().
              This file runs on the server and is deduplicated per-request using React.cache().
            


            

              

                

                  

                    
                    
                    
                  

                  

                    TS
                    lib/auth.ts
                  

                

                

                  
                

              

              
// lib/auth.ts
import { cookies } from 'next/headers';
import { getServerAuth, type Session } from 'reqix/next';

export interface AppUser {
  id: string;
  email: string;
  name: string;
}

export interface AppSession extends Session {
  accessToken: string;
  refreshToken?: string;
  user?: AppUser;
}

const BACKEND_URL = process.env.AUTH_BACKEND_URL || 'https://api.yourbackend.com';

export function getAppAuth() {
  const cookieStore = cookies();

  return getServerAuth<AppSession>({
    cookies: cookieStore,
    baseURL: BACKEND_URL, // Automatically applied to auth.fetch
    refreshSession: async (session: AppSession) => {
      // Called when token is near expiry or 401 is received
      const res = await fetch(`${BACKEND_URL}/api/auth/refresh`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ refreshToken: session.refreshToken }),
      });

      if (!res.ok) {
        throw new Error(`Refresh failed with status ${res.status}`);
      }

      const data = await res.json();
      return {
        ...session,
        accessToken: data.accessToken,
        refreshToken: data.refreshToken ?? session.refreshToken,
      };
    },
  });
}

            

          


          
          

            

              
2

              

                
Edge Middleware Proactive Refresh

                middleware.ts
              

            

            

              Next.js Server Components cannot modify cookies during streaming render.
              createAuthMiddleware runs at the Edge before the page renders,
              inspects the token expiration, refreshes near-expiry tokens, and updates both the incoming request headers
              and outgoing response cookies!
            


            

              

                

                  

                    
                    
                    
                  

                  

                    TS
                    middleware.ts
                  

                

                

                  
                

              

              
// middleware.ts
import { createAuthMiddleware } from 'reqix/next';
import type { AppSession } from './lib/auth';

const BACKEND_URL = process.env.AUTH_BACKEND_URL || 'https://api.yourbackend.com';

export const middleware = createAuthMiddleware<AppSession>({
  loginUrl: '/login',
  publicPaths: ['/', '/login', '/api/auth'],
  protectedPaths: ['/dashboard', '/account', '/settings'],
  refresh: async (session: AppSession) => {
    const res = await fetch(`${BACKEND_URL}/api/auth/refresh`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ refreshToken: session.refreshToken }),
    });

    if (!res.ok) throw new Error('Middleware token refresh rejected');

    const data = await res.json();
    return {
      ...session,
      accessToken: data.accessToken,
      refreshToken: data.refreshToken ?? session.refreshToken,
    };
  },
});

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};

Auth Route Handlers

                app/api/auth/[...reqix]/route.ts
              

            

            

              Expose secure /api/auth/login, /api/auth/refresh, and
              /api/auth/logout
              endpoints with built-in CSRF defenses and HttpOnly cookie persistence:
            


            

              

                

                  

                    
                    
                    
                  

                  

                    TS
                    app/api/auth/[...reqix]/route.ts
                  

                

                

                  
                

              

              
// app/api/auth/[...reqix]/route.ts
import { createAuthRouteHandlers } from 'reqix/next';
import type { AppSession } from '@/lib/auth';

const BACKEND_URL = process.env.AUTH_BACKEND_URL || 'https://api.yourbackend.com';

const handlers = createAuthRouteHandlers<AppSession>({
  login: async (credentials) => {
    const res = await fetch(`${BACKEND_URL}/api/auth/login`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(credentials),
    });
    if (!res.ok) throw new Error('Invalid email or password');
    return res.json(); // Sets HttpOnly cookie automatically!
  },
  refresh: async (session) => {
    const res = await fetch(`${BACKEND_URL}/api/auth/refresh`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ refreshToken: session?.refreshToken }),
    });
    if (!res.ok) throw new Error('Refresh failed');
    return res.json();
  },
  logout: async (session) => {
    if (session?.refreshToken) {
      await fetch(`${BACKEND_URL}/api/auth/logout`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ refreshToken: session.refreshToken }),
      }).catch(() => {});
    }
  },
});

export const POST = handlers.POST;

// lib/client-auth.ts ('use client')
import { createAuth, createWebLock } from 'reqix';
import type { AppSession } from './auth';

export const auth = createAuth<AppSession>({
  baseURL: process.env.NEXT_PUBLIC_API_URL || 'https://api.yourbackend.com',
  getSession: () => {
    if (typeof window === 'undefined') return null;
    const raw = localStorage.getItem('app_session');
    return raw ? JSON.parse(raw) : null;
  },
  saveSession: (s) => localStorage.setItem('app_session', JSON.stringify(s)),
  clearSession: () => localStorage.removeItem('app_session'),
  
  // Cross-tab mutual exclusion: only one tab refreshes at a time!
  lock: createWebLock(),
  enableCrossTabSync: true,

  refreshSession: async (session) => {
    const res = await fetch('/api/auth/refresh', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ refreshToken: session.refreshToken }),
    });
    return res.json();
  },
});

// Full HTTP client with GET, POST, PUT, DELETE + single-flight auth
export const api = auth.client;

            

          

        

      


      
      

        
⚛️ TanStack Query (React Query) Integration

        

          reqix pairs seamlessly with TanStack Query (React Query).
          Because api.get and api.post automatically parse JSON response bodies and throw
          typed HttpError on non-2xx responses, your query functions stay clean, concise, and predictable.
        


        
1. Global QueryClient Provider (app/providers.tsx)

        

          Configure TanStack Query's QueryClient once in your root client provider. You can set a global
          queryFn that delegates directly to reqix:
        


        

          

            

              

                
                
                
              

              

                TSX
                app/providers.tsx
              

            

            

              
            

          

          
'use client';

import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { ReactNode, useState } from 'react';
import { api } from '@/lib/client-auth';

export function Providers({ children }: { children: ReactNode }) {
  // Create a stable QueryClient instance per client session
  const [queryClient] = useState(
    () =>
      new QueryClient({
        defaultOptions: {
          queries: {
            // Default query function using Reqix
            queryFn: async ({ queryKey }) => {
              const url = typeof queryKey[0] === 'string' ? queryKey[0] : '';
              const res = await api.get(url);
              return res.data;
            },
            staleTime: 1000 * 60 * 5, // 5 minutes fresh window
            refetchOnWindowFocus: true,
            retry: 1, // Reqix handles transport retries internally
          },
        },
      })
  );

  return (
    <QueryClientProvider client={queryClient}>
      {children}
    </QueryClientProvider>
  );
}

        


        
2. Queries & Mutations with Automatic Single-Flight Auth

        

          When client components mount concurrently, TanStack Query may initiate multiple queries at once.
          reqix guarantees that if the access token is expired, only 1 silent refresh
          executes,
          preventing race conditions and token desync:
        


        

          

            

              

                
                
                
              

              

                TSX
                components/PostList.tsx
              

            

            

              
            

          

          
'use client';

import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { api } from '@/lib/client-auth';

interface Post {
  id: number;
  title: string;
}

export function PostList() {
  const queryClient = useQueryClient();

  // 1. Fetching data: Automatic Bearer token injection and proactive refresh
  const { data: posts, isLoading, error } = useQuery({
    queryKey: ['/api/posts'],
    queryFn: async () => {
      const res = await api.get<Post[]>('/api/posts');
      return res.data; // Fully typed Post[]
    },
  });

  // 2. Mutations: Automatic Bearer token with optimistic UI update
  const createMutation = useMutation({
    mutationFn: async (title: string) => {
      const res = await api.post<Post>('/api/posts', { title });
      return res.data;
    },
    onSuccess: () => {
      // Invalidate queries to trigger background refetch
      queryClient.invalidateQueries({ queryKey: ['/api/posts'] });
    },
  });

  if (isLoading) return <div>Loading posts...</div>;
  if (error) return <div>Failed to load posts</div>;

  return (
    <div>
      <ul>
        {posts?.map((p) => (
          <li key={p.id}>{p.title}</li>
        ))}
      </ul>
      <button onClick={() => createMutation.mutate('New TanStack Post')}>
        Add Post
      </button>
    </div>
  );
}

        


        

          💡
          

            Why TanStack Query + Reqix is the optimal stack:
            TanStack Query excels at in-memory caching, window-focus revalidation, and garbage collection, while
            reqix provides the ultra-lightweight zero-dependency HTTP client, automatic timeout/retry,
            and single-flight JWT token refresh engine.
          

        

      


      
      

        
✈️ Single-Flight Concurrency Guarantee

        

          When 10 concurrent requests fire as a token expires, reqix ensures that exactly
          1 network refresh call takes place:
        


        

          

            

              

                
                
                
              

              

                FLOW
                Single-Flight Concurrency Guarantee Pipeline
              

            

          

          
Request 1 ──┐
Request 2 ──┼──► [Token Expired] ──► [Single-Flight Lock] ──► Exactly 1 Refresh Call ──► All 10 Succeeded (200 OK)
Request 3 ──┘

        


        
Two-Tier Refresh: Proactive vs Reactive

        
    
          
  • 
            Tier 1: Proactive (Pre-flight): If now >= expiresAt - 30s,
            reqix refreshes the token before sending the request. No 401 error is ever
            encountered.
          
    • 
          
  • 
            Tier 2: Reactive (Post-response): If the backend revokes the token or rejects with
            401 Unauthorized,
            reqix catches the 401, checks if another request already refreshed the token, runs a
            single-flight refresh if needed,
            and retries the request transparently.
          
    •

                Number of retry attempts on network failures or retry status codes.
              

              

                retryStatusCodes

                [408, 429, 500, 502, 503, 504]

                duplex

                Required for streaming bodies in Node.js 18+ and edge runtimes.
